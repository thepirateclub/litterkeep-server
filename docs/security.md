# Security profile

> **About this document.** Security profile: passwords, TLS, account canonicalisation, resource limits and what never reaches the logs.
>
> Documentation navigation — [docs/README.md](README.md), project status — [STATUS.md](../STATUS.md).

Passwords are generated by the OS/TLS CSPRNG and stored as Argon2id PHC records.
Bootstrap secrets are never passed in argv and never printed; on Linux
`test-accounts.tsv` has mode `0600`. TLS is implemented with rustls, and an
unknown CA or an invalid SAN is rejected.

Every external account login is canonicalised through the local-domain enum
policy. A full external-domain address never becomes a credential path or a
Store owner. Mailbox, script and message operations always take the owner from
the authenticated session, never from an arbitrary owner ID supplied by the
client.

Protocol sizes, literals, DATA, the AST, the diagnostic journal, the Store
quota, connection admission, worker channels and downstream output are all
bounded. A stalled stage has a deadline; a slow reader loses only its own
session lease.

Server logs and the runtime control surface never contain passwords, TLS keys
or mail bodies. The test CA is intended only for a local acceptance environment.
